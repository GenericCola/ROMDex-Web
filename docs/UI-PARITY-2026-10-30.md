# Desktop UI parity restoration — local work in progress

The desktop UI is the visual and interaction reference. The October 29 authentication and hosting checkpoint did not establish UI parity.

## Evidence and cause

The three supplied screenshots show the deployed web workspace, the desktop's full-height work tray, and the desktop's split work/details view. The split layout is original; the web's permanent account/project strip, recovery strip and port-status footer are additions.

The read-only source reference is `GenericCola/ROMDex` commit `28c0ce4d449e655661dd7469999a6dc56779f28f`. Twelve fetched files were checked against their Git blob hashes. This repository snapshot is older than the installed October 23 repairs. Preserve the accepted web domain/status corrections; do not replace them with older desktop rules.

The source explains the visual drift:

- Desktop `selector-view.mjs` builds compact selector cards, hierarchy/count subtitles, status lights and tile settings. The React port had replaced them with `port-selector-row` buttons.
- Desktop `app.mjs` renders field tags and overlaid native selects. The port rendered plain uppercase values.
- Desktop updates the initial title placeholder with breadcrumbs and the current view name/counts. The React port retained `Your Project`.
- Desktop row actions appear on hover/focus, alongside drag and selection controls. The port displayed an `Actions` column with permanent up/down/add buttons.
- Original scoped CSS was retained, but reconstructed DOM/classes bypassed many of its rules.

Git history attributes the work-table foundation to `49ebea0254555ced8681d664845858654d774070` (October 22 incomplete-port checkpoint), last changed for filters in `1027af55a71e2eb9a2efc8f68e2ef605cefdaeb1`. These differences predate the latest OAuth work; the later account strip added more permanent vertical space. Repo documentation specifies React rendering, but this is not independently verified as a user requirement. React does not require a redesign.

## Local restoration

Reuse original DOM/classes and pure presentation rules. Keep authenticated identity separation, memory-only credentials, durable local drafts, reviewed delivery, uncertain-operation recovery and PWA update safeguards.

The first local pass restores selector cards and tile settings, view headings/breadcrumbs/counts, colored field controls, compact row actions, and moves account/recovery/PWA controls into a header tools dialog. Save and recovery failures must remain visible, including during an open modal. The tools dialog's children remain mounted so moving the controls does not stop service-worker registration.

Tile settings retain the existing validated 2 MiB browser image limit rather than silently copying the older desktop's 8 MiB input/resizing path. Field edits remain local queue operations; native delivery requires connection review. Unknown native values stay visible rather than being silently normalized.

## Verification boundaries

A local synthetic fixture renders the actual React components with memory-only task persistence and a native image adapter for standalone preview. Its CSP forbids remote connections. It is outside production source/export and contains no credentials or user workspace. The supported managed preview is used only for internal browser QA, not a new hosted application.

Actual initial browser checks: split/full tray rendering; tools opens account/recovery controls and closes with focus restoration; Tile Settings opens and applies a synthetic title edit. These do not verify live writes, account identity changes or deployed behavior.

Remaining interaction parity is tracked explicitly: drag/reparent, multi-selection/grouping, status popups and inline create/edit need source-backed restoration and checks. Do not call the first visual pass complete parity. Production remains on `0988f5a3bcd860665fccfa0d88146c450fdc686d` until reviewed publication. SC-001 sharing stays off. NPCDex is not part of this restoration.
